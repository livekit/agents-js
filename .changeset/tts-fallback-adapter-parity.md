Make the TTS `FallbackAdapter` behave like the Python one. It fails over on any provider error, not only API errors (non-API errors are logged at error level with their stack). A provider that fails after its audio started ends the utterance without replaying it, is marked unavailable and is now reported as a `tts_error` that is recoverable when the adapter has another provider (unrecoverable for a single-provider adapter), so it no longer counts towards closing the session. Failed providers are probed by the requests that skip or fail over them, with a short `stream()` request instead of `synthesize()`, so `inference.TTS` recovers. A probe's `fallback_activated` notice is never forwarded, and a probe that hangs after some audio counts as failed.

Behavior changes: an idle adapter no longer probes on its own, so `recoveryDelayMs` is now the minimum interval between probes of one provider instead of a timer. `markUnAvailable()` only marks the instance and no longer starts recovery. A request never fails while a provider remains untried: when every provider it tried has failed, it tries the ones it skipped as unavailable, in priority order. An instance is restored when a probe succeeds or when it serves a request with audio. `tts_availability_changed`, `stt_availability_changed` and `llm_availability_changed` are typed on the adapters' event types. `StreamAdapter` no longer throws when the wrapped TTS reports an error and nothing listens on the wrapper.
